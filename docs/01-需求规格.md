# 需求规格说明书

> 依据当前仓库中的数据库设计、建表脚本、界面说明和 UML 时序图整理。字段与状态取值以 `sql/init.sql`、`docs/04-数据库设计.md` 为准，界面入口以 `docs/05-界面与设计模式.md` 为准。

## 1. 项目概述

校园里有大量闲置教材、数码配件和文体用品。本系统是一套在本地运行的桌面应用，供高校学生发布和流转这些物品，并记录流转结果与信用；管理员维护账号、类别和违规物品。

系统形态为 Java Swing 桌面程序，业务数据保存在 SQLite 文件 `data/campus_resource.db`，表结构由 `sql/init.sql` 创建。程序按界面、业务、数据访问分层。最终交付可双击运行的 Jar。

## 2. 用户角色

| 角色 | 标识 | 能做的事 |
| --- | --- | --- |
| 未登录用户 | — | 注册、登录 |
| 普通学生 | `STUDENT` | 发布和管理自己的物品，检索、收藏，发起和处理流转，评价，查看本人信用和本人统计 |
| 系统管理员 | `ADMIN` | 具备学生端的浏览和统计能力，并额外管理用户、违规下架、类别和全平台统计 |

注册产生的账号默认为学生。学生看不到「管理」菜单。账号另有状态：`ACTIVE` 可登录，`DISABLED` 不可登录。

## 3. 功能需求

### 3.1 用户账号

- 注册时填写账号、密码和确认密码。账号在系统内唯一，密码与确认密码必须一致。注册成功后回到登录界面。
- 数据层同时保存昵称。昵称未单独填写时，与账号相同。联系电话、邮箱可选。
- 登录时提交账号和密码。账号不存在、密码不正确、账号已禁用，都停留在登录界面并提示原因。登录成功后进入主窗口，并记下当前登录用户。
- 密码只保存摘要，不保存明文。
- 主窗口「我的信用」展示当前用户信用分。新用户信用分为 100，取值范围 0 到 100。
- 「退出登录」清除当前登录状态并回到登录界面。

### 3.2 闲置物品发布

学生可以发布物品。每条物品记录包含：

| 字段 | 要求 |
| --- | --- |
| 名称 | 必填 |
| 分类 | 必填，且为已启用的类别 |
| 描述 | 可选 |
| 期望价格 | 非负数字；未填写时按 0 保存 |
| 交易方式 | 出售 `SALE`、交换 `EXCHANGE`、赠送 `FREE` |
| 状态 | 新发布为在架 `AVAILABLE` |
| 标签 | 可选 |
| 图片 | 可选，只保存本地路径，不把图片内容写入数据库 |

物品状态还包括：流转处理中 `RESERVED`、已完成 `COMPLETED`、已下架 `OFFLINE`。

发布前校验名称、分类和价格。校验不通过或保存失败时留在发布界面并提示。发布者可以修改自己的物品，也可以下架自己尚未成交的物品。下架后状态为 `OFFLINE`，并记录下架时间。已完成的物品不能由发布者下架。

### 3.3 检索与收藏

物品列表是登录后的默认页。用户可以按分类、关键词、最低价和最高价筛选，条件可以单独使用，也可以组合。关键词按名称、描述和标签模糊匹配。可以清空条件后重新查询。

列表显示名称、分类、价格、状态和发布人。没有结果时显示「没有符合条件的物品」。

同一列表按入口切换范围：

- 浏览物品：在架物品
- 我的发布：当前用户发布的物品
- 我的收藏：当前用户已收藏的物品

用户可以收藏或取消收藏。同一用户对同一物品只能有一条收藏记录。只有在架、且不是自己发布的物品可以发起流转意向。

### 3.4 供需沟通与流转

流转由意向发起人向物品发布者提出，双方不能是同一人。一条物品可以先后产生多条流转记录。每条记录保存物品、双方、交易方式、留言、成交价格、状态和时间。

流转状态：

| 状态 | 含义 |
| --- | --- |
| `PENDING` | 已发起，等待发布者处理 |
| `ACCEPTED` | 发布者已接受 |
| `REJECTED` | 发布者已拒绝 |
| `COMPLETED` | 发起人已确认完成 |
| `CANCELLED` | 已取消 |

处理过程：

1. 发起人提交意向。系统写入流转记录，并把物品改为流转处理中。两步在同一事务中完成，任一步失败则全部回滚。
2. 发布者接受或拒绝待处理意向。拒绝或取消后，若物品尚未成交，恢复为在架，以便再次流转。
3. 发布者接受后，由发起人确认完成。完成时在同一事务中把流转和物品都改为已完成，写入完成时间，并按物品类别的减排系数记下本次减排估算值。

界面分「进行中」和「已完成」两个页签，显示物品、对方、方式、状态和时间。没有记录时显示「还没有流转记录」。

### 3.5 评价与信用

只有已完成的流转可以评价。发起人和发布者各评价对方一次，不能评价自己，也不能对同一条流转重复评价。

评价包含 1 到 5 分的评分，文字内容可选。保存评价和更新被评价人信用分在同一事务中完成，任一步失败则全部回滚。提交成功后刷新信用分显示。不满足条件时提示无法提交，不写入评价。评分如何换算成信用分增减，该部分正在完善中。

### 3.6 数据统计

统计已完成流转的数量，并按物品分类汇总，同时给出对应的减排估算。学生只看自己参与的流转，管理员看全平台。

类别上的减排系数用于成交时计算本次估算值。初始类别和系数由 `sql/init.sql` 写入：书籍教材 0.5、电子产品 2.0、生活用品 0.3、体育用品 0.8、其他 0.1。管理员维护类别时可以调整系数。

统计结果可以导出为 CSV。

### 3.7 管理员后台

管理员菜单包含用户管理、违规下架、类别维护和全平台统计。

- 用户管理：查看账号、角色和信用分，可以禁用或恢复账号。禁用后该用户不能登录。
- 违规下架：将指定物品设为已下架。
- 类别维护：新增类别、修改名称和说明、停用类别。停用后不能再被选为新物品的分类，已有物品仍保留原分类。
- 全平台统计：与第 3.6 节相同的统计界面，数据范围为全部已完成流转。

## 4. 非功能需求

- 非法输入在业务层拦截，并在当前界面提示。价格必须是非负数字，评分必须是 1 到 5 的整数，角色、状态和交易方式只能取本文列出的值。更细的非法输入清单该部分正在完善中。
- 登录、发布、下架、流转状态变化、评价和管理员操作写入日志，便于核对。
- 业务数据持久化到 SQLite。开启外键。账号唯一，收藏和评价按文档中的唯一约束防止重复。
- 发起意向、确认成交、提交评价这三类跨表操作使用事务。
- 界面不编写业务判断，业务层不绘制界面。数据库连接和当前登录用户全局各保留一份。
- 最终提供可双击运行的 Jar，本机不依赖单独安装的数据库服务。

## 5. 可拓展任务

暂时不考虑实际实现在线多用户服务、账号找回、图片内容入库、数据备份恢复和智能推荐。物品图片只保留可选的本地路径。

Swing 界面、业务代码和打包按后续迭代实现。实现时以本说明书和 `sql/init.sql` 为准；若表结构或状态流转有调整，先改数据库设计和本说明书，再改代码。
