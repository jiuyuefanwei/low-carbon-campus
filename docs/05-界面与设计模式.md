# 界面与设计模式

> 界面、复用与交付负责人：张天慧。第 1/2 周只确定界面清单、菜单结构和设计模式选用。Swing 编码、Maven 打包从第 3 周开始。

## 1. 界面清单

启动后先进入登录界面。登录成功后进入主窗口，主窗口按菜单切换下面各界面。学生看不到管理后台。

| 界面 | 角色 | 入口 | 界面上有什么 | 用户可做的操作 |
| --- | --- | --- | --- | --- |
| 登录 | 未登录用户 | 启动程序 | 账号、密码、登录按钮、注册入口、错误提示 | 提交登录；打开注册 |
| 注册 | 未登录用户 | 登录界面中的「注册」 | 账号、密码、确认密码、注册按钮 | 提交注册；返回登录。默认角色为学生 |
| 物品列表 | 学生、管理员 | 主窗口默认页；菜单「浏览物品」「我的发布」「我的收藏」 | 分类、关键词、最低价、最高价；结果表（名称、分类、价格、状态、发布人） | 搜索、清空条件、查看详情、收藏或取消收藏。在架且不是自己发布的物品可以发起意向 |
| 发布物品 | 学生 | 菜单「发布物品」；从「我的发布」进入时为修改 | 名称、分类、描述、价格、标签、交换或出售 | 发布、保存修改、下架。下架只对自己发布且未成交的物品可用 |
| 流转记录 | 学生 | 菜单「流转」 | 两个页签：进行中、已完成。列：物品、对方、方式（出售/交换）、状态、时间 | 接受或拒绝意向；双方确认后标记成交；成交后进入评价 |
| 评价 | 学生 | 已完成流转中的「评价」 | 对方、物品、分数、短评 | 提交一次评价。提交后界面刷新信用分 |
| 统计 | 学生、管理员 | 菜单「统计」 | 按分类的流转数量、减排估算、导出按钮 | 查看统计；导出 CSV。学生看自己参与的流转，管理员看全平台 |
| 管理后台 | 管理员 | 菜单「管理」 | 三个页签：用户、物品、类别 | 查看用户与信用分；违规物品下架；新增、改名、停用类别 |

物品列表在没有结果时显示「没有符合条件的物品」。流转记录为空时显示「还没有流转记录」。

登录失败、必填项为空、价格不是非负数字时，停在当前界面并给出提示，不进入下一屏。

## 2. 菜单结构

登录前没有主菜单，只有登录界面和注册入口。

学生登录后的主菜单：

```text
物品
├── 浏览物品          → 物品列表（全部在架物品）
├── 发布物品          → 发布物品
├── 我的发布          → 物品列表（只看自己的）
└── 我的收藏          → 物品列表（只看已收藏）
流转
├── 进行中的意向      → 流转记录（进行中）
└── 已完成的流转      → 流转记录（已完成，可评价）
统计
└── 流转与减排        → 统计（本人范围，可导出 CSV）
账户
├── 我的信用          → 显示当前信用分
└── 退出登录          → 回到登录界面
```

管理员在以上菜单之外增加：

```text
管理
├── 用户管理          → 管理后台 / 用户
├── 违规下架          → 管理后台 / 物品
├── 类别维护          → 管理后台 / 类别
└── 全平台统计        → 统计（全平台范围，可导出 CSV）
```

主窗口用同一块内容区切换界面。菜单项负责打开对应界面，不在菜单监听器里写业务判断。

界面与业务模块的对应关系：

| 界面 | 调用的模块 |
| --- | --- |
| 登录、注册、我的信用 | 用户 |
| 物品列表、发布物品 | 物品 |
| 流转记录、评价 | 流转、评价 |
| 统计 | 统计 |
| 管理后台 | 用户、物品；类别数据来自数据访问层 |

## 3. 设计模式选用

第 3 周再按下面的位置编码。本阶段先定模式、所在模块和选用理由。

| 模式 | 用在哪里 | 理由 |
| --- | --- | --- |
| 单例 | `common`：数据库连接；当前登录用户 | 桌面程序一次运行只服务一个登录用户，连接和登录状态全局只有一份 |
| 工厂 | `gui`：按菜单命令创建物品列表、发布、流转记录、统计、管理后台 | 主窗口只负责切换，每个界面的构造集中在一处，后面加界面时主窗口不用跟着改 |
| 策略 | `item`：关键词、分类、价格区间三种筛选可单独或组合使用；`stats`：不同类别使用不同的减排估算方法 | 筛选条件和减排口径后续可能增加，界面只收集条件，具体算法可以替换 |
| 观察者 | `gui`：发布、成交、下架、评价完成后通知物品列表和统计界面刷新 | 一次业务操作会同时影响多个界面，各界面自己注册刷新，互不直接调用 |

单例、工厂、策略是本项目约定的三种基本模式。观察者补在界面层，用来处理「数据变了，多个页面一起更新」。

后续实现时的类名约定：

| 模式 | 建议类名 | 模块 |
| --- | --- | --- |
| 单例 | `Database`、`Session` | `common` |
| 工厂 | `PanelFactory` | `gui` |
| 策略 | `ItemFilter`、`CarbonEstimator` | `item`、`stats` |
| 观察者 | `DataChangeListener` | `gui` |

`docs/03-模块与接口.md` 第 5 节的设计模式预选以本文件为准。
