# 数据库设计

> 数据库使用 SQLite，建表脚本放在 `sql/init.sql`。

## 1. 表清单

本系统围绕用户管理、物品发布、物品检索、收藏、供需流转和用户评价等核心功能，设计以下六张数据表。

| 表名 | 用途 |
| --- | --- |
| user | 保存用户账号、密码摘要、角色、信用分及账号状态 |
| category | 保存物品类别及分类相关信息 |
| item | 保存用户发布的闲置物品信息、交易方式及物品状态 |
| favorite | 保存用户收藏物品的记录 |
| trade | 保存物品流转意向、处理状态及成交信息 |
| review | 保存流转完成后的用户评价及评分 |

## 2. 字段说明

### 2.1 user（用户表）

用于保存普通学生用户和系统管理员的基本信息及账号数据。

| 字段名 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | INTEGER | 主键，自增 | 用户唯一编号 |
| username | TEXT | 非空，唯一 | 登录账号 |
| password_hash | TEXT | 非空 | 加密后的密码摘要 |
| display_name | TEXT | 非空 | 用户昵称或姓名 |
| phone | TEXT | 可空 | 联系电话 |
| email | TEXT | 可空 | 邮箱 |
| role | TEXT | 非空，默认 STUDENT | 用户角色：STUDENT / ADMIN |
| credit_score | REAL | 非空，默认 100 | 用户信用分 |
| status | TEXT | 非空，默认 ACTIVE | 账号状态：ACTIVE / DISABLED |
| created_at | TEXT | 非空 | 账号创建时间 |
| updated_at | TEXT | 非空 | 信息更新时间 |

说明：系统通过 `role` 字段区分普通用户和管理员；密码以摘要形式保存，不存储明文密码。

### 2.2 category（物品分类表）

用于维护系统中的物品类别，方便用户发布物品和按类别检索。

| 字段名 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | INTEGER | 主键，自增 | 分类唯一编号 |
| name | TEXT | 非空，唯一 | 分类名称 |
| description | TEXT | 可空 | 分类说明 |
| carbon_factor | REAL | 非空，默认 0，且不小于 0 | 单件物品减排估算系数 |
| is_active | INTEGER | 非空，默认 1 | 分类是否启用，0/1 |
| created_at | TEXT | 非空 | 分类创建时间 |

说明：减排估算系数用于后续低碳数据统计。具体数值需要根据项目组确定的估算方法进行设置，不能直接使用未经核实的数据。

### 2.3 item（闲置物品表）

用于保存用户发布的闲置物品信息，支持物品发布、修改、下架及检索。

| 字段名 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | INTEGER | 主键，自增 | 物品唯一编号 |
| seller_id | INTEGER | 非空，外键，关联 user.id | 发布者编号 |
| category_id | INTEGER | 非空，外键，关联 category.id | 所属分类编号 |
| name | TEXT | 非空 | 物品名称 |
| description | TEXT | 可空 | 物品描述 |
| expected_price | REAL | 可空，非负 | 期望价格 |
| trade_type | TEXT | 非空 | 交易方式：SALE / EXCHANGE / FREE |
| status | TEXT | 非空，默认 AVAILABLE | 物品状态：AVAILABLE / RESERVED / COMPLETED / OFFLINE |
| tags | TEXT | 可空 | 物品标签 |
| image_path | TEXT | 可空 | 物品图片本地存储路径 |
| created_at | TEXT | 非空 | 发布时间 |
| updated_at | TEXT | 非空 | 信息更新时间 |
| taken_down_at | TEXT | 可空 | 下架时间 |

说明：物品图片暂采用本地路径保存，不直接将图片二进制数据存入数据库。物品状态用于区分可流转、流转中、已完成和已下架等情况。

### 2.4 favorite（收藏表）

用于记录用户收藏的物品，支持收藏和取消收藏功能。

| 字段名 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | INTEGER | 主键，自增 | 收藏记录编号 |
| user_id | INTEGER | 非空，外键，关联 user.id | 收藏用户编号 |
| item_id | INTEGER | 非空，外键，关联 item.id | 被收藏物品编号 |
| created_at | TEXT | 非空 | 收藏时间 |

约束：`user_id` 和 `item_id` 组合唯一，避免同一用户重复收藏同一物品。

### 2.5 trade（流转记录表）

用于记录用户发起物品流转意向、物品发布者处理意向以及最终成交或交换的全过程。

| 字段名 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | INTEGER | 主键，自增 | 流转记录编号 |
| item_id | INTEGER | 非空，外键，关联 item.id | 对应物品编号 |
| initiator_id | INTEGER | 非空，外键，关联 user.id | 意向发起人编号 |
| owner_id | INTEGER | 非空，外键，关联 user.id | 物品发布者编号 |
| trade_type | TEXT | 非空 | 流转方式：SALE / EXCHANGE / FREE |
| status | TEXT | 非空，默认 PENDING | 流转状态：PENDING / ACCEPTED / REJECTED / COMPLETED / CANCELLED |
| message | TEXT | 可空 | 意向沟通留言 |
| agreed_price | REAL | 可空，非负 | 双方确认的成交价格 |
| carbon_reduction | REAL | 非空，默认 0，且不小于 0 | 本次流转的减排估算值 |
| created_at | TEXT | 非空 | 意向发起时间 |
| updated_at | TEXT | 非空 | 流转记录更新时间 |
| completed_at | TEXT | 可空 | 流转完成时间 |

说明：

 `initiator_id` 表示发起流转意向的用户，`owner_id` 表示物品发布者，两者不能为同一用户。
 流转状态用于记录意向从发起、接受或拒绝到完成或取消的变化。
 `carbon_reduction` 用于保存完成流转后的减排估算值，具体计算方式由系统业务逻辑确定。

### 2.6 review（评价表）

用于保存物品流转完成后，交易双方对彼此的评价信息。

| 字段名 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| id | INTEGER | 主键，自增 | 评价记录编号 |
| trade_id | INTEGER | 非空，外键，关联 trade.id | 对应流转记录编号 |
| reviewer_id | INTEGER | 非空，外键，关联 user.id | 评价人编号 |
| reviewee_id | INTEGER | 非空，外键，关联 user.id | 被评价人编号 |
| rating | INTEGER | 非空，取值 1—5 | 评价评分 |
| content | TEXT | 可空 | 评价内容 |
| created_at | TEXT | 非空 | 评价时间 |

约束：

 同一流转记录中，同一用户只能提交一次评价。
 评价人和被评价人不能为同一用户。
 一条流转记录最多对应双方各一条评价记录。

## 3. 关系

系统主要实体之间的关系如下：

 **用户与物品：一对多关系。** 一个用户可以发布多个物品，每个物品只能对应一个发布用户，通过 `item.seller_id` 关联 `user.id`。
 **分类与物品：一对多关系。** 一个分类可以包含多个物品，每个物品属于一个分类，通过 `item.category_id` 关联 `category.id`。
 **用户与物品收藏：多对多关系。** 一个用户可以收藏多个物品，一个物品也可以被多个用户收藏，通过 `favorite` 表建立关联。
 **物品与流转记录：一对多关系。** 一个物品在不同时间可能产生多条流转意向记录，每条流转记录对应一个物品，通过 `trade.item_id` 关联 `item.id`。
 **用户与流转记录：一对多关系。** 用户可以发起多条流转意向，也可以作为物品发布者参与多条流转记录，分别通过 `trade.initiator_id` 和 `trade.owner_id` 关联用户表。
 **流转记录与评价：一对多关系。** 一条已完成的流转记录最多对应两条评价记录，分别由流转双方提交，通过 `review.trade_id` 关联 `trade.id`。
 **用户与评价：一对多关系。** 一个用户可以提交多条评价，也可以收到多条评价，分别通过 `review.reviewer_id` 和 `review.reviewee_id` 关联用户表。

## 4. 完整性与事务

### 4.1 数据完整性约束

为保证数据库数据的正确性和一致性，采用以下约束措施：

 **主键约束：** 每张表均设置自增主键，保证记录具有唯一标识。
 **外键约束：** 通过外键维护用户、物品、分类、收藏、流转及评价之间的关联关系。
 **唯一约束：** 用户账号唯一；同一用户不能重复收藏同一物品；同一流转记录中同一用户不能重复评价。
 **非空约束：** 对账号、物品名称、分类名称、流转参与者等必要字段设置非空约束。
 **检查约束：** 对用户角色、物品状态、交易方式、评价评分和价格等设置取值范围限制。
 **业务规则校验：** 在 Service 层检查用户身份、物品状态、流转参与关系等，防止非法操作。

### 4.2 事务处理

以下业务操作涉及多张表或多个数据更新，需要使用 JDBC 事务保证数据一致性。

**（1）物品流转完成**

当流转双方确认完成时，需要在同一个事务中：

 更新 `trade` 表中的流转状态及完成时间；
 更新 `item` 表中的物品状态；
 保存本次流转的减排估算值。

如果其中任一步骤执行失败，则回滚整个事务，避免出现流转记录已完成但物品状态未更新的情况。

**（2）提交用户评价**

用户提交评价并更新信用分时，需要在同一个事务中：

 向 `review` 表插入评价记录；
 更新 `user` 表中被评价用户的信用分。

如果评价保存或信用分更新失败，则回滚事务，保证评价数据和信用分的一致性。

**（3）发起流转意向**

用户发起流转意向时，需要在同一个事务中完成：

 向 `trade` 表插入流转记录；
 根据系统约定更新 `item` 表中的物品状态（例如设置为流转处理中）。

如果物品状态更新失败，则回滚流转记录的插入操作。

事务由 Service 层统一管理，DAO 层负责具体数据库操作。事务执行成功后提交，发生异常时回滚，确保数据操作的原子性。

**数据库文件说明：**

本系统实际运行时使用 `data/campus_resource.db` 保存业务数据，`sql/init.sql` 用于创建数据库表结构和初始化基础数据。数据库文件与初始化脚本相互独立，项目提交时保留初始化脚本，实际数据库文件可由各成员在本地初始化生成。
