# 低碳校园资源循环流转桌面系统

面向高校校园的轻量化本地桌面应用，用来流转闲置教材、数码配件、文体用品等物品。学生可以发布、检索、收藏物品，发起意向并完成流转与互评；管理员维护用户、类别和违规物品。系统使用 Java、Swing 和 SQLite，最终打包为可直接运行的 Jar。

仓库地址：<https://github.com/jiuyuefanwei/low-carbon-campus>

## 功能

1. **用户账号**：注册、登录、密码加密存储、学生与管理员角色区分、输入校验。
2. **闲置物品**：发布、修改、下架。字段包括名称、分类、描述、价格、状态、标签。
3. **检索与收藏**：按分类、关键词、价格区间筛选，支持模糊搜索和收藏。
4. **供需与流转**：发起意向、生成流转记录、更新成交或交换状态。
5. **评价与信用**：流转完成后互评，维护并展示信用分数。
6. **统计报表**：流转数量、低碳减排估算、导出 CSV。
7. **管理员后台**：用户管理、违规下架、类别维护、全平台统计。

图片存储、备份恢复、智能推荐不在本期范围内。

## 技术栈

| 类别 | 选型 |
| --- | --- |
| 语言 | Java |
| 界面 | Java Swing |
| 数据库 | SQLite + JDBC |
| 构建 | Maven |
| 测试 | JUnit 5 |

设计上按模块划分职责，数据访问与界面分开。数据库连接使用单例，对象创建使用工厂，统计口径等可替换规则使用策略。关键输入做校验，成交与评价等跨表操作放在同一事务中。

## 协作方式

`main` 已设置保护，不能直接推送或在网页上直接提交。所有改动从功能分支发起 Pull Request，审查通过后再合并。

1. 从最新的 `main` 拉出自己的分支，命名为 `feature/姓名-简述`，例如 `feature/zhangsan-db-schema`。
2. 只修改自己负责的文件，并用自己的 Git 账号提交。不要把别人的改动放进自己的提交。
3. 推送功能分支，向 `main` 发起 Pull Request。说明改了什么、对应哪份文档或哪个模块。
4. 至少一名组员审阅后再合并。有修改意见时在原分支上继续提交，不要新开一个无关分支绕过评论。
5. 合并后删除已完成的功能分支，下次从最新的 `main` 重新开分支。

```bash
git checkout main
git pull origin main
git checkout -b feature/姓名-简述
# 修改、提交后
git push -u origin HEAD
```

然后在 GitHub 上创建 Pull Request，目标分支选择 `main`。
